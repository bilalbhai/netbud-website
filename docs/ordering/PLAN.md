## Owner-controlled setup — do not share secrets in chat

1. **Confirm business identity:** registered legal name, ABN, GST registration details and product tax classifications. Accountant reviews gross-price extraction, deposit/refund treatment and invoice template. This unlocks correction of the currently inaccurate no-GST statement; no extra 10% is added.
2. **Confirm saleable scopes:** entry NFC card/printing/programming scope at A$39, finishes and add-ons, quantity tiers, stock/made-to-order, included revisions and real production arrangements. Confirm which service packages can be fixed-price. No invented stock or discounts.
3. **Approve architecture:** unchanged static site eventually on Cloudflare Pages, server API and Supabase; Resend provisional email. Approving local Phase B is separate from approving account creation, DNS or production.
4. **Backend account:** owner creates eligible Supabase Free project, selects an appropriate region after privacy review, enables account MFA and keeps credentials in the provider's secret store. Use local disposable database for fixtures; reserve free slots for isolated staging/production as available. No accidental upgrade.
5. **Hosting account:** owner creates/authorizes Cloudflare Free access, account MFA and least-privilege repository integration for NetBud only. Preview branch stays separate from production; never enable automatic main deployment for unfinished orders. Stage output must include public assets only, excluding docs, migrations, fixtures, backups and secrets.
6. **Email provider:** owner creates/approves Resend Free (or explicitly selects Brevo), verifies account eligibility and sender domain. Configure `noreply@netbud.com.au` From, `sales@netbud.com.au` Reply-To. Test actual recipient receipt, bounce/failure handling and OTP latency. A successful API response alone is not inbox delivery.
7. **Preserve incoming forwarding:** export current GoDaddy DNS first. Keep MX, existing forwarding TXT, DMARC and verification data. Add aliases for bilal, sales, noreply, enquiries, info and careers through the actual forwarding provider, not invented DNS alias records. Owner supplies sales' separate Gmail destination privately in their dashboard; do not guess it or read Gmail automatically.
8. **Sender DNS:** copy exact DKIM/SPF/return-path records from the chosen provider; review conflicts before saving. Use the provider's designated sending subdomain where supported; do not replace incoming apex MX. Never create two SPF TXT records at the same host. Verify alignment with existing DMARC, and test forwarding after changes. No DNS mutations are part of A/B.
9. **Owner admin:** controlled invitation to bilal@netbud.com.au, set strong password directly in Auth UI and enroll TOTP. Verify owner identity before granting owner role through privileged setup. Store recovery codes safely; no default credentials or public registration. Invite staff only when owner chooses assignments.
10. **Revolut:** owner applies for Merchant within verified Business account, confirms Australian online/hosted-payment capability and actual fees, then supplies sandbox credentials directly to server secret storage. Never send API keys/card data in chat. Confirm free-host policy before embedding any payment interface; current proposal forbids embedded card entry. Live activation needs separate sign-off.
11. **Fulfilment:** confirm manual Australia Post purchasing, A$14.95 domestic shipping, A$99 physical-only free threshold, A$0 pickup by arrangement at 67–71 Great Western Highway, Parramatta NSW 2150. Enter tracking manually; do not invent dispatch scans or pickup hours.
12. **Operations/privacy:** approve processors/regions and policy drafts; establish encrypted off-site backups with tested restore and an operator for capacity alerts, email dead letters, account pauses and refunds. Confirm retention/legal holds and support escalation.
13. **Production migration later:** review staged design/URLs, TLS, email and route tests. Approve DNS changes with exported before/after records and a rollback window. For apex Pages, transfer DNS hosting to Cloudflare only after all existing records are reconciled and DNSSEC state handled. GoDaddy can remain registrar. Test apex/www HTTPS and incoming/outgoing mail. No changes until explicit approval.

Example server-only configuration names (not values): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TURNSTILE_SECRET_KEY`, `RESEND_API_KEY`, `EMAIL_WEBHOOK_SECRET`, `OTP_HMAC_SECRET`, `RATE_LIMIT_HMAC_SECRET`, `REVOLUT_SANDBOX_SECRET_KEY`, `REVOLUT_WEBHOOK_SECRET`, `APP_ORIGIN`, `EMAIL_FROM`, `EMAIL_REPLY_TO`, `PAYMENTS_MODE`. Public configuration may contain an allowlisted API origin and Turnstile site key, never privileged credentials. Default `PAYMENTS_MODE=disabled`; production and sandbox key namespaces must be distinct.

## Launch blockers and limits

Not complete: provider accounts/eligibility, legal identity/ABN and invoice review, saleable options, secure decoder benchmark, verified email/sales forwarding, automatic backup destination/scheduler/restore, Merchant integration, free-host card-policy confirmation and full acceptance tests. Free storage/email/CPU/egress quotas and database pausing can interrupt operation; there is no promise of unlimited sales or permanent zero pricing. No recurring software bill may be activated to bypass a blocker without owner approval. Manual unpaid ordering can launch only after its own security, receipt, privacy and owner approval gates pass.

## Rollback

Phase A changes only documentation and a snapshot: return to the previous branch to preview the unchanged application, or revert the documentation commit. Do not reset or delete unrelated local work.

For later stages, keep the previous static build and feature flags: disable new order entry/payment initiation, restore prior shop/enquiry links, keep existing private orders readable and exportable. Do not delete production records or reverse captured payments through a code rollback. Use forward-compatible, additive migrations and explicit reviewed repair migrations; never assume SQL down migrations are safe for financial history. Stop workers safely before rollback; retain outbox deduplication and webhook reconciliation. Back up before each schema deployment and rehearse restoration in isolation. DNS rollback uses recorded previous values with mail checks and propagation allowance; it is a separately authorized operation. Existing GitHub Pages restrictions still apply to any proposed rollback hosting choice.
