## Technical requirements

- Plain HTML5, CSS3, vanilla JavaScript and local SVG/image assets.
- Google Fonts through a stylesheet link, with system-font fallbacks.
- No React or other frontend framework; no Node.js, npm or build process required by the site.
- `index.html` opens directly from the filesystem. Ordinary script tags, relative page links and no required local-data fetches or JavaScript modules.
- Compatible with GitHub Pages, other static hosts and a future custom domain without server-side URL rewriting.
- One primary stylesheet, `css/style.css`; shared behaviour in `js/main.js`; editable package data in `js/products.js`; shared settings in `js/config.js`.
- Site files live at the repository root, with `images/` and `previews/` alongside them.
- Third-party delivery, analytics and payment integrations remain configurable and are described honestly.

## Integrations, SEO and maintenance

- Email and WhatsApp details are configured; form endpoints and hosted payment links are initially blank.
- Without a live endpoint, forms prepare reviewable enquiry drafts and never claim delivery. Opening an email/WhatsApp draft is not sending it.
- Marketing permission is separate, optional and unchecked by default.
- Social profiles and analytics remain configurable; analytics requires opt-in before loading.
- No private API keys, prospect data or payment credentials belong in source files.
- Every page needs its own title, description, social metadata, semantic headings and local image paths.
- Production canonical/share URLs, `robots.txt` and `sitemap.xml` must use the eventual real hostname. Do not invent one.
- Dynamic product metadata has crawler limitations; separate static product HTML pages are the fallback for unique social previews.
- Draft policies require review against actual business arrangements before launch; the site does not claim legal compliance.
- Documentation should explain beginner editing, contacts, catalogue changes, integrations and GitHub Pages publication without a build command.
